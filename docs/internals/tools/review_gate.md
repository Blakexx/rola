# `review_gate.py`

Mirrors [`tools/review_gate.py`](../../../tools/review_gate.py) and the hook that runs it,
[`tools/git-hooks/post-commit`](../../../tools/git-hooks/post-commit).

THE REVIEW GATE (Blake, 2026-11-06: "advisory, opus"): a change reviewed by an LLM against the repository's standards,
[`CONSTITUTION.md`](../../CONSTITUTION.md) and [`KERNEL_STANDARDS.md`](../../KERNEL_STANDARDS.md), every finding citing
the rule it breaks and the changed line it breaks it at. It sits beside the deterministic gates (the lint roster, the
SASS gate, the tests), never in place of them, and beside the coordinator's and Blake's own reading of what lands.

WHAT IS REVIEWED: one commit (`HEAD` by default), a branch's range (`--range origin/carry-k5..HEAD`, the local review
in place of a pull request), or the staged diff (`--staged`). The prompt carries the instructions, both standards
whole, the change's message(s) and its diff (up to 200 KB inline; past that its head, the rest read from the files),
the diff leaving out recorded and generated bytes (lab results, the reference locks, the manifests, the step floors).

WHAT IT LOOKS FOR beyond a rule broken at a changed line: what the change makes OBSOLETE -- for each mechanism added or
replaced, what else in the tree does that job or fed the old one (a parallel path, a field whose consumers were
replaced, a decision computed that nothing acts on, an unreachable guard, a doc stating the old form): the semantic
case of dead code, still read or compiling, that no lint sees (2026-11-07: the capability rows' structure flags, read
only by a residency selection no kernel consumed, outlived the families that replaced them). And the docs' ALTITUDE: a
changed passage says why a piece exists and how it connects, not what the code does step by step, and points nothing
outside the repo.

THE REVIEWER: `claude -p` in the checkout, Opus by default (`--model`), its tools read-only (Read, Grep, Glob) so it
checks the touched files, their mirror pages and anything else before asserting, its output a fixed JSON schema (a
summary and findings: rule, file, line, severity `block` or `warn`, claim, evidence). Slash commands, MCP servers and
session persistence are off. A report is cached by everything it read -- the prompt's version, the model, the
standards, the message, the diff -- and kept in the git common dir's `rola-review/`, shared by every worktree;
`--show N` prints the last N.

<a id="pipelined"></a>PIPELINED (Blake, 2026-11-08): nothing waits on a review. The next commit is made while it runs;
each report is read when it lands, and its findings go into the next commit after it, each block fixed or answered in
words. A review may trail a commit or two; a push to the default branch, which publishes (CI mirrors it to the public
repository, `.github/workflows/mirror.yml`), waits until every review of its commits has landed and been read.

ADVISORY: `tools/git-hooks/post-commit` starts a review of `HEAD` detached after every commit, so a commit is neither
slowed nor refused; it is skipped mid-rebase or without the `claude` CLI, and it runs from
the checkout's own venv (git's rola.venv), saying so and skipping when that names none (`bazel run //:dev_env`). The first review
(Opus, the carve planner's commit 4fbcf920) took 236 s and $1.65 and named two fair warnings. Blocking, when the
advisory period's false positives are known, keeps the pipeline: no commit waits on its review, and the push to the
default branch is what is refused while one of its commits has a cited `block` finding no later commit answers, by a
fix or by a `Review-Override:` trailer naming the rule and the reason -- so `--no-verify` is never the way out.
